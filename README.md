# Next Instagram · 수담 SUDAM

CEOS 24기 프론트엔드 수담 팀이 Next.js로 만든 인스타그램 클론입니다. 5주차에는 홈 피드에서 게시물을 읽고 작성자 프로필과 상세 화면을 오가는 기능을 구현했습니다. 6주차에는 피드에서 눌러 둔 북마크를 내 프로필에서 다시 찾아볼 수 있도록 저장됨 탭을 연결하고, 스크롤하며 다음 게시물을 기다리는 화면을 개선했습니다.

[배포 사이트](https://next-instagram-24th-self.vercel.app/) · [5주차 제출 PR](https://github.com/CEOS-Developers/next-instagram-24th/pull/9) · [6주차 제출 PR](https://github.com/CEOS-Developers/next-instagram-24th/pull/13)

## 5주차 · 피드에서 프로필과 게시물 상세로

홈 피드의 작성자 이름을 누르면 해당 계정의 프로필로 이동합니다. 프로필에서 게시물을 열어 댓글을 남기고 모달을 닫으면 둘러보던 그리드로 돌아옵니다. [5주차 과제 안내](docs/assignment-week5.md)

### 화면 구성과 이동

- **동적 라우팅** — 사용자 이름으로 프로필(`/[username]`)을, 게시물 ID로 상세 페이지(`/p/[postId]`)를 엽니다.
- **공통 UI** — 아바타, 작성자 링크, 사진 갤러리를 컴포넌트로 분리해 홈·프로필·상세에서 재사용합니다.
- **프로필과 게시물 그리드** — 계정 정보와 작성한 게시물을 함께 보여줍니다. 넓은 화면에서는 4열, 좁은 화면에서는 3열로 표시하며 사진 위에 마우스를 올리면 좋아요와 댓글 수를 볼 수 있습니다.
- **프로필과 상세 간 이동** — 그리드에서 사진을 누르면 상세 모달이 열리고 작성자 이름을 누르면 프로필로 이동합니다. 게시물 주소로 직접 접속하거나 새로고침하면 독립된 상세 페이지가 열립니다.

### 화면별 기능

| 화면 | 할 수 있는 일 |
| --- | --- |
| 홈 피드 | 최신 게시물부터 스크롤하며 보기, 여러 장의 사진을 화살표로 넘기기, 좋아요·저장 켜고 끄기 |
| 게시물 상세 | 사진 순서 확인, 좋아요 누르기, 댓글 작성 및 목록에서 확인, 닫기 버튼·Esc·배경 클릭으로 모달 닫기 |
| 내 프로필 | 이름과 소개 편집, 소개에 링크 추가, 프로필 사진 위 말풍선에 노트 작성 |
| 다른 계정 | 홈 추천 목록이나 상대 프로필에서 팔로우·언팔로우, 상대 프로필에서 변경된 팔로워 수 확인 |
| 내비게이션 | 넓은 화면에서 한글 메뉴가 있는 사이드바 사용, 모바일에서 하단 탭으로 홈·프로필 이동 |

사용자와 게시물의 기본 정보는 목데이터로 구성했습니다. 좋아요, 댓글, 저장, 팔로우와 프로필 수정 사항은 브라우저의 `localStorage`에 보관되어 같은 브라우저에서 새로고침해도 유지됩니다.

## 6주차 · 북마크한 게시물 다시 보기

5주차의 북마크 버튼은 게시물마다 저장 여부를 기억했습니다. 이번 Sprint의 목표는 **저장한 게시물을 내 프로필에서 찾아 다시 열고, 그 자리에서 저장을 취소할 수 있게 하는 것**이었습니다.

### 저장부터 취소까지

1. 홈 피드에서 게시물의 북마크를 누릅니다. 직접 올린 게시물도 상세 화면을 열면 저장할 수 있습니다.
2. **내 프로필 → 저장됨**을 열면 이전에 북마크한 게시물이 작성자에 관계없이 모여 있습니다.
3. 저장된 게시물을 열어 북마크를 해제하고 상세 화면을 닫으면 그 게시물이 목록에서 사라집니다. 마지막 게시물까지 해제하면 빈 목록 안내가 표시됩니다.

### 무한 스크롤과 로딩 화면

| 화면 | 목록 끝에 가까워지면 |
| --- | --- |
| 프로필의 저장됨 탭 | 처음에 최대 네 개를 표시합니다. 하단의 ‘더 보기’ 버튼이 화면에 가까워지면 다음 네 개까지 펼칩니다. 마지막 묶음을 표시하면 버튼이 사라집니다. |
| 홈 피드 | 다음 페이지를 요청하고 기존 게시물 아래에 아바타와 사진 영역을 본뜬 스켈레톤을 표시합니다. 응답이 오면 카드가 이어지고, 요청에 실패하면 같은 위치에서 다시 시도할 수 있습니다. |

두 화면 모두 Intersection Observer로 목록 하단을 관찰합니다. 저장됨 탭은 브라우저에 있는 데이터에서 표시 개수만 늘리고, 홈 피드는 다음 페이지를 요청하는 동안 중복 호출을 막습니다.

### Sprint Backlog

| 우선순위 | 작업 | 상태 |
| --- | --- | --- |
| 1 | 기존 북마크를 저장됨 탭에 표시하고 상세 화면의 저장·취소 반영 | 구현 |
| 2 | 저장 목록을 네 개씩 펼치고 마지막 묶음에서 관찰 종료 | 구현 |
| 3 | 피드 추가 로딩 중 스켈레톤 표시 및 실패 시 재시도 지원 | 구현 |
| 4 | 팀원별 담당 최종 확인, 브라우저에서 저장·취소·새로고침 점검 및 팀 회고 | 팀 확인 예정 |

### 구현 회고

저장됨 탭을 만들면서 먼저 살펴본 것은 5주차에 저장한 북마크였습니다. 목록과 버튼이 같은 게시물 ID의 저장 값을 읽도록 연결하니, 기존 게시물을 다시 저장할 필요가 없었고 상세 화면에서 누른 저장 취소도 목록에 반영할 수 있었습니다.

스켈레톤을 배치할 때는 실제로 기다림이 생기는 지점을 기준으로 삼았습니다. 저장 목록의 다음 네 개는 즉시 펼칠 수 있었고, 홈 피드에서는 응답이 올 때까지 시간이 필요했습니다. 그래서 홈에서는 읽던 게시물을 계속 볼 수 있도록 다음 카드가 들어올 자리만 로딩 화면으로 표시했습니다.

## 실행 방법

저장소 루트에서 아래 명령을 차례로 실행합니다.

```bash
npm ci
npm run dev
```

터미널에 표시된 주소로 접속합니다. 기본 주소는 [localhost:3000](http://localhost:3000/)입니다.

| 명령 | 용도 |
| --- | --- |
| `npm run lint` | ESLint로 코드 검사 |
| `npm run build` | 타입 검사 및 프로덕션 빌드 |
| `npm run start` | 빌드한 앱 실행 |
