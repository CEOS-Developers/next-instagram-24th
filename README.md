# Next Instagram · SCOLOCK

CEOS 24기 프론트엔드 SCOLOCK 팀(이상민, 이상빈)이 Next.js App Router로 만든 인스타그램 클론입니다. 모바일 화면(iPhone 16, 393×852)을 기준으로 구현했습니다. 5주차에는 프로필과 게시물 상세 화면을 오가는 기본 구조를 만들었고, 6주차에는 홈 피드를 무한 스크롤과 스켈레톤 UI로 구현하고 다른 사용자 프로필과 팔로우·좋아요·북마크를 더했습니다.

[배포 사이트](https://next-instagram-24th-theta.vercel.app/) · [5주차 제출 PR](https://github.com/CEOS-Developers/next-instagram-24th/pull/11)

## 5주차 · 프로필과 게시물 상세

프로필 그리드에서 사진을 누르면 게시물 상세로 이동하고, 상세에서 다시 프로필로 돌아올 수 있습니다. [5주차 과제 안내](docs/assignment-week5.md)

- **동적 라우팅** — 사용자 이름으로 프로필(`/[username]`)을, 게시물 ID로 상세 페이지(`/p/[postId]`)를 엽니다. 없는 게시물 주소로 들어오면 404 페이지를 보여 줍니다.
- **공통 UI** — 하단 내비게이션과 데스크톱 사이드바가 같은 메뉴 정보를 공유하고, 지금 있는 페이지의 아이콘을 강조합니다.
- **게시물 그리드** — 한 줄에 3개씩 3:4 비율로 표시합니다. 간격과 크기는 실제 인스타그램을 개발자 도구로 재서 맞췄습니다.
- **사진 넘기기** — 여러 장짜리 게시물은 좌우 버튼이나 스와이프로 넘기고, 아래 점으로 순서를 확인합니다.

## 6주차 · 홈 피드와 사용자 상호작용

이번 Sprint의 목표는 **홈 피드를 끊김 없이 이어지는 목록으로 만들고, 다른 사용자의 게시물에 좋아요·북마크·팔로우로 반응할 수 있게 하는 것**이었습니다. [6주차 과제 안내](docs/assignment-week6.md)

### 화면별 기능

| 화면 | 할 수 있는 일 |
| --- | --- |
| 홈 피드 | 최신 게시물부터 스크롤하며 보기, 사진 넘기기, 좋아요·저장 켜고 끄기, 작성자 이름을 눌러 프로필로 이동, 날짜를 눌러 상세로 이동 |
| 다른 사용자 프로필 | `film_notes`, `slow_walks`, `minihompy` 계정의 게시물 보기, 팔로우·언팔로우와 팔로워 수 변화 확인 |
| 내 프로필 | 저장됨 탭에서 북마크한 게시물 모아 보기, 팔로우한 만큼 팔로우 수 반영 |
| 게시물 상세 | 좋아요·저장, 뒤로 가기를 누르면 이전 페이지로 돌아가기 (기록이 없으면 작성자 프로필로) |

좋아요, 저장, 팔로우는 브라우저의 `localStorage`에 보관되어 같은 브라우저에서 새로고침해도 유지됩니다. 프로필 탭은 `/[username]/saved`처럼 탭마다 주소가 달라서 새로고침해도 보던 탭이 유지됩니다.

### 무한 스크롤과 스켈레톤 UI

| 단계 | 동작 |
| --- | --- |
| 처음 접속 | 서버에서 최신 게시물 5개를 미리 그려서 보냅니다. |
| 목록 끝에 가까워지면 | 목록 맨 아래의 표시 요소를 Intersection Observer로 관찰하다가, 화면에서 200px 앞까지 오면 `/api/feed?offset=N`으로 다음 5개를 요청합니다. |
| 기다리는 동안 | 카드와 같은 크기의 스켈레톤 2개를 표시하고, 응답이 오면 기존 목록 아래에 카드를 붙입니다. |
| 마지막 게시물까지 받으면 | 표시 요소를 없애서 더 이상 요청하지 않습니다. |

요청이 진행되는 동안에는 관찰을 멈춰서 같은 페이지를 두 번 요청하지 않도록 했습니다. 요청에 실패하면 다시 요청하지 않고 안내 문구를 보여 줍니다.

### 구현 회고

이번 Sprint에서는 홈 피드와 프로필을 나눠 맡았습니다. 피드는 화면 → 무한 스크롤 → 스켈레톤 순서로 단계를 나눠, 단계마다 화면에서 확인하면서 진행했습니다. 좋아요·북마크 버튼은 프로필 쪽에서 먼저 만든 것을 피드 카드에서도 그대로 가져다 써서, 피드에서 누른 좋아요가 상세와 저장됨 탭에도 똑같이 반영되도록 했습니다.

## 협업 규칙

- **Branch** — `feature/작업내용`, `docs/작업내용`. `master`에 직접 push하지 않고 PR로 머지합니다.
- **Commit** — `feat`, `fix`, `style`, `refactor`, `docs`, `chore` 타입을 붙입니다.
- **PR** — 템플릿(관련 이슈, 변경 사항, 스크린샷, 체크리스트)을 채우고, 팀원 리뷰와 Approve 뒤 머지하고 브랜치를 삭제합니다.
- **Code** — 컴포넌트 파일은 PascalCase, import는 `@/` 절대경로를 씁니다. 한 화면에서만 쓰는 컴포넌트는 그 폴더의 `_components`에, 여러 화면에서 쓰는 컴포넌트는 `components/`에 둡니다.

## 파일 구조

```text
next-instagram-24th/
├── docs/                         # 5·6주차 과제 안내 원문
├── public/                       # 아이콘, 프로필·게시물 사진
├── app/
│   ├── layout.tsx                # 하단 내비게이션, 사이드바
│   ├── page.tsx                  # 홈 피드
│   ├── _components/              # 홈 헤더, 피드 목록(무한 스크롤)
│   ├── _lib/                     # 기본 사용자 정보, 좋아요·북마크 저장
│   ├── api/feed/route.ts         # 다음 피드 페이지 조회
│   ├── [username]/               # 프로필과 탭(saved, reels, reposts, tagged)
│   └── p/[postId]/               # 게시물 상세, 사진 넘기기, 좋아요·북마크 버튼
├── components/                   # 게시물 카드, 스켈레톤, 그리드, 내비게이션 등 공통 컴포넌트
├── data/                         # 게시물·프로필 목데이터
├── types/                        # 게시물 타입
└── utils/                        # 날짜 표시 함수
```

## 실행 방법

```bash
pnpm install
pnpm dev
```

[localhost:3000](http://localhost:3000/)으로 접속합니다.

| 명령 | 용도 |
| --- | --- |
| `pnpm lint` | ESLint로 코드 검사 |
| `pnpm build` | 타입 검사 및 프로덕션 빌드 |
| `pnpm start` | 빌드한 앱 실행 |
