# next-instagram-24th

CEOS 24기 프론트엔드 5·6주차 과제로 만든 **Next.js 인스타그램 클론**입니다.
5주차에는 프로필, 게시물 상세, 좋아요·댓글·팔로우를 구현했습니다.
6주차에는 홈 피드에 무한 스크롤과 스켈레톤 UI를 적용하고, 게시물 저장 및 본인 프로필의 저장됨 기능을 추가했습니다.

<br>

## 실행 방법

```bash
npm install
npm run dev
```

[http://localhost:3000](http://localhost:3000)에 접속하면 전체 사용자의 게시물이 표시되는 홈 피드가 열립니다.

| 주소 | 화면 |
| --- | --- |
| `/` | 전체 사용자 게시물을 최신순으로 표시하는 홈 피드 |
| `/cristiano`, `/leomessi` | 사용자 프로필 |
| `/ngannou` | 현재 접속 사용자로 가정한 은가누의 프로필 |
| 본인 프로필의 저장됨 탭 | 저장한 게시물을 최근 저장한 순서로 표시 |
| `/[username]/post/[postId]` | 게시물 상세 (새로고침·직접 접속 시 단독 페이지) |
| 프로필에서 게시물 클릭 | 같은 주소의 게시물 상세 모달 |

<br>

## 기술 스택

- **Next.js 16** (App Router, Turbopack, `cacheComponents`)
- **React 19**, **TypeScript**
- **Tailwind CSS 4** (디자인 토큰은 `src/styles/tokens.css`의 `@theme`로 관리)
- 서버 없이 목업 데이터를 사용하고, 사용자 상호작용은 `localStorage`에 저장합니다.

### 홈 피드

- 모든 사용자의 게시물을 작성일 기준 최신순으로 표시합니다.
- `FeedPostCard`에 작성자, 상대 시간, 이미지 캐러셀, 좋아요 수, 댓글 수와 본문을 표시합니다.
- 긴 본문은 일부만 표시하고, 본문의 더 보기 버튼으로 펼칠 수 있습니다.
- 작성자 프로필과 게시물 상세 화면으로 이동할 수 있습니다.
- 사이드바의 홈 아이콘을 누르면 `/`로 이동합니다.

### Intersection Observer 기반 무한 스크롤

- `useInfiniteScroll` 훅에서 목록 맨 아래의 감지 요소를 관찰합니다.
- 화면 하단에서 200px 떨어진 지점부터 감지하여 다음 게시물을 미리 표시합니다.
- 처음에는 게시물 3개를 표시하고, 하단에 도달할 때마다 3개씩 추가합니다.
- `isLoading`, `hasMore`, 타이머 참조를 확인하여 로딩 중이거나 데이터가 끝났을 때 추가 로딩을 막습니다.
- Observer 콜백의 `requested` 값으로 같은 관찰에서 중복 호출을 방지합니다.
- 컴포넌트가 해제되면 Observer와 대기 중인 로딩 타이머를 정리합니다.
- 준비된 목데이터를 모두 표시하면 로딩을 종료하고 완료 문구를 보여줍니다.

현재는 서버에서 전달받은 목데이터의 표시 개수를 늘리는 방식입니다.
실제 API에서 페이지별 데이터를 요청하거나, 마지막 게시물 이후 처음부터 반복하는 방식은 적용하지 않았습니다.

### Skeleton UI

- `FeedPostSkeleton`을 피드 카드와 비슷한 구조로 구성했습니다.
- 추가 게시물을 표시하는 동안 아바타, 이미지, 버튼, 텍스트 영역의 자리를 유지합니다.
- 목데이터는 즉시 준비되므로 스켈레톤을 확인할 수 있도록 800ms의 로딩 지연을 두었습니다.
- 로딩 상태를 스크린 리더에 전달하는 안내 문구도 제공합니다.

### 게시물 저장 및 저장됨 탭

- 홈 피드와 게시물 상세 화면에서 저장·저장 취소를 할 수 있습니다.
- `saveStorage.ts`에서 현재 사용자 ID별로 저장한 게시물 ID를 `localStorage`에 보관합니다.
- 본인 프로필(`/ngannou`)에만 저장됨 탭을 표시하고, 최근 저장한 게시물부터 보여줍니다.
- 저장을 취소하면 저장됨 목록에서도 해당 게시물이 제거됩니다.
- 저장한 게시물이 없으면 빈 상태 안내를 표시합니다.
- `useSyncExternalStore`와 커스텀 이벤트로 현재 화면의 저장 상태를 동기화하고, `storage` 이벤트로 다른 탭의 변경도 반영합니다.
- 다른 작성자의 게시물도 올바른 상세 페이지로 이동하도록 작성자별 경로를 사용합니다.

### 회고 및 개선할 점

- 하단 감지 로직을 공통 훅으로 분리해 홈 피드 외의 목록에서도 재사용할 수 있도록 구성했습니다.
- 저장 상태를 공통 저장소로 관리하여 홈 피드, 상세 화면, 저장됨 목록 사이의 상태 불일치를 줄였습니다.
- 다른 작성자의 저장 게시물로 이동할 때 발생한 모달 라우팅 충돌은 상세 페이지로 직접 이동하도록 수정했습니다.
- 프로필 그리드의 무한 스크롤과 그리드용 스켈레톤은 후속 작업으로 남아 있습니다.
- 실제 API를 연결할 때는 페이지 조회 함수와 요청 실패 처리, 재시도 흐름을 추가하고 임시 로딩 지연을 제거할 예정입니다.

## 구현하면서 신경 쓴 점

### Server Component와 Client Component 구분

화면 구조와 데이터 조회는 Server Component에 두고, 상호작용이 필요한 부분만 `"use client"`로 분리했습니다.

| Server Component | Client Component |
| --- | --- |
| 프로필 페이지, 게시물 상세(`PostDetail`), 작성자 헤더, 본문, 썸네일 | 좋아요·저장 버튼(`PostActions`), 댓글 목록·입력, 이미지 캐러셀, 모달, 팔로우 버튼, 프로필 탭 |

예를 들어 썸네일(`PostThumbnail`)은 서버에서 그리고, hover 시 보이는 좋아요·댓글 수(`PostThumbnailStats`)만 클라이언트 컴포넌트로 분리해 저장된 상태를 반영합니다.

### 게시물 상세 모달 (Parallel + Intercepting Routes)

프로필에서 게시물을 누르면 주소는 `/[username]/post/[postId]`로 바뀌지만, 프로필 위에 모달로 열립니다.
같은 주소로 새로고침하거나 직접 접속하면 단독 상세 페이지가 보입니다.

- `@modal` 슬롯과 `(.)post/[postId]`로 프로필 안에서의 이동을 가로챕니다.
- 모달은 `<dialog>`의 `showModal()`을 사용해 포커스 가두기와 Esc 닫기를 브라우저 기본 동작으로 처리합니다.
- 상세 화면은 `PostDetail` 하나를 `variant="page" | "modal"`로 재사용합니다.

### localStorage 상태와 `useSyncExternalStore`

좋아요, 댓글, 팔로우, 게시물 저장 상태는 `localStorage`에 저장하고 `useSyncExternalStore`로 구독합니다.

- 서버 렌더링과 첫 클라이언트 렌더링은 목업 초기값을 사용해 hydration 불일치를 막습니다.
- 값이 바뀌면 커스텀 이벤트로 알려서, 상세에서 누른 좋아요가 그리드 숫자에도 바로 반영됩니다.
- 다른 탭에서 바꾼 값은 `storage` 이벤트로 반영됩니다.

### Next.js 16 `cacheComponents` 대응

- `params`처럼 요청마다 달라지는 값은 `Suspense` 안에서 읽습니다.

## 💬 6주차 Review Questions

### 1. Intersection Observer API를 활용한 무한 스크롤의 구현 방식과 구현 과정에서 고려한 사항에 대해 설명해주세요.

Intersection Observer API는 특정 요소가 화면 또는 지정한 영역과 교차하는 상태의 변화를 비동기로 알려주는 브라우저 API입니다.
이번 프로젝트에서는 홈 피드 맨 아래에 감지용 요소(sentinel)를 두고, 이 요소가 화면 하단 근처에 들어오면 다음 게시물을 표시하도록 구현했습니다.

#### 구현 방식

1. `FeedList`에서 처음 표시할 게시물 수를 3개로 설정하고, 목록 맨 아래의 `<div>`에 `sentinelRef`를 연결합니다.
2. `useInfiniteScroll` 훅의 `useEffect`에서 Observer를 생성하고, `observe()`로 감지 요소를 관찰합니다.
3. `root: null`로 브라우저 화면을 기준으로 삼고, `rootMargin: "0px 0px 200px 0px"`로 하단 감지 영역을 200px 확장합니다. `threshold`는 `0`으로 설정합니다.
4. 감지 요소의 `isIntersecting`이 `true`가 되면 `onLoadMore()`를 호출합니다.
5. `FeedList`의 `loadMore()`가 로딩 상태를 변경하고, 800ms 후 표시 개수를 3개 늘립니다. 로딩 중에는 `FeedPostSkeleton`을 표시합니다.
6. 로딩이 끝나면 훅에서 다시 관찰합니다. 감지 요소가 여전히 감지 영역 안에 있으면 다음 추가 로딩으로 이어질 수 있습니다.
7. 전체 목데이터를 모두 표시하면 `hasMore`가 `false`가 되어 관찰을 중단하고 완료 문구를 표시합니다.

현재 구현은 이미 전달받은 목데이터에서 `slice()`로 표시 범위를 늘리는 방식입니다.
800ms 지연은 스켈레톤 UI를 확인하기 위한 것으로, 실제 네트워크 요청 시간은 아닙니다.

#### 구현 과정에서 고려한 사항

| 고려 사항 | 적용 방식과 이유 |
| --- | --- |
| 중복 로딩 방지 | `isLoading`과 타이머 참조로 진행 중인 로딩을 확인합니다. Observer 내부에서는 `requested`를 즉시 변경하여 React 상태가 반영되기 전의 중복 콜백도 막습니다. |
| 데이터 끝 처리 | `hasMore`가 `false`이면 추가 로딩과 관찰을 중단하여 같은 데이터를 불필요하게 처리하지 않도록 했습니다. |
| 감지 시점 | 화면 하단을 200px 확장한 영역에서 감지하여 사용자가 목록 끝에 도달하기 전에 추가 로딩을 시작합니다. |
| 로딩 피드백 | 카드와 비슷한 모양의 스켈레톤과 스크린 리더용 로딩 안내를 제공하여 다음 게시물을 준비 중임을 알립니다. |
| Observer와 타이머 정리 | Effect 정리 함수에서 `disconnect()`를 호출하고, 컴포넌트 해제 시 타이머도 취소합니다. 이미 대기 중인 Observer 콜백은 `requested` 검사로 무시합니다. |
| 재사용성과 의존성 관리 | 하단 감지는 `useInfiniteScroll`에, 표시 개수와 로딩 상태는 `FeedList`에 두었습니다. `loadMore`는 `useCallback`으로 관리하고 훅은 필요한 값이 바뀔 때 관찰을 다시 설정합니다. |
